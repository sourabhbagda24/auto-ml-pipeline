STEP 1 — Load Dataset
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : CSV file ko pandas se read karo
  Input        : CSV_PATH (file ka path)
  Output       : Raw DataFrame (df)
  Prints       : Shape, column names, pehli 3 rows
  Example      : titanic.csv → (891, 12) shape

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 2 — Remove Irrelevant Columns
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Useless columns automatically detect karke drop karo
  Input        : Raw DataFrame
  Output       : Cleaned DataFrame (useless cols removed)

  3 Types of columns jo drop hoti hain:
  ┌─────────────────┬──────────────────────────────────────────┐
  │ Type            │ Condition                                │
  ├─────────────────┼──────────────────────────────────────────┤
  │ High Missing    │ >50% values missing hain                 │
  │ Constant        │ Sirf 1 unique value hai (koi info nahi)  │
  │ ID-like         │ Unique values == Total rows (ID column)  │
  └─────────────────┴──────────────────────────────────────────┘

  NOTE : Target column kabhi drop nahi hoti — protected hai.
  Config: MISSING_THRESHOLD = 0.5 (50%)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 3 — Column Identification
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Har column ko Numerical ya Categorical mein sort karo
  Input        : Cleaned DataFrame
  Output       : num_cols list + cat_cols list

  Logic:
  → int/float dtype  →  Numerical column
  → object/string    →  Categorical column
  → SPECIAL CASE: Agar numerical column mein <=10 unique values
    hain toh use Categorical treat karo
    (Example: Pclass = 1,2,3 → sirf 3 values → categorical)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 4 — Missing Value Handling
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Missing/NaN values ko fill karo
  Input        : DataFrame with missing values
  Output       : DataFrame with no missing values

  Strategy:
  ┌──────────────────┬────────────────────────────────────────┐
  │ Column Type      │ Fill Strategy                          │
  ├──────────────────┼────────────────────────────────────────┤
  │ Numerical        │ Median se fill karo                    │
  │ Categorical      │ Mode (most frequent) se fill karo      │
  └──────────────────┴────────────────────────────────────────┘

  Kyun Median? — Outliers se affect nahi hota
  Kyun Mode?   — Category mein sabse common value logical hai

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 5 — Outlier Handling (IQR Capping)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Extreme values ko cap karo (delete nahi, sirf limit karo)
  Input        : Numerical columns
  Output       : Capped numerical values

  Formula:
    Q1  = 25th percentile
    Q3  = 75th percentile
    IQR = Q3 - Q1

    Lower Bound = Q1 - 1.5 × IQR
    Upper Bound = Q3 + 1.5 × IQR

    Value < Lower  →  Lower pe set karo
    Value > Upper  →  Upper pe set karo

  Example:
    Age column mein 150 value hai → unrealistic
    Upper bound = 65 → 150 ko 65 pe cap kar do

  Config: OUTLIER_IQR_FACTOR = 1.5 (standard value)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 6 — Encoding & Scaling
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Data ko numbers mein convert karo + scale karo
  Input        : Mixed type DataFrame
  Output       : Fully numerical DataFrame (ML ke liye ready)

  A) Categorical Encoding:
  ┌────────────────────┬────────────────────────────────────────┐
  │ Unique Values      │ Method                                 │
  ├────────────────────┼────────────────────────────────────────┤
  │ <=10 unique values │ OneHotEncoding (dummy columns banao)   │
  │ >10 unique values  │ LabelEncoding  (0,1,2,3... assign karo)│
  └────────────────────┴────────────────────────────────────────┘

  B) Target Column Encoding:
    Agar target string hai (e.g. "yes"/"no") → LabelEncoder

  C) Numerical Scaling:
    StandardScaler → mean=0, std=1 pe scale karo
    Kyun? — SVM, KNN, LogReg distance-based hain, scale matter karta hai

STEP 8 — Determine Task Type
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Auto-detect karo ki problem Classification hai ya Regression
  Input        : Target column
  Output       : "classification" ya "regression" string

  Logic:
  ┌──────────────────────────────┬──────────────────────────────┐
  │ Condition                    │ Task                         │
  ├──────────────────────────────┼──────────────────────────────┤
  │ Target dtype = object/string │ Classification               │
  │ Target unique values <= 20   │ Classification               │
  │ Target unique values > 20    │ Regression                   │
  └──────────────────────────────┴──────────────────────────────┘

  Example:
    Survived → 0 or 1 → 2 unique values → Classification
    House Price → 50,000 values → Regression

STEP 9 — Class Imbalance Handling (SMOTE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Agar classes unequal hain toh balance karo
  Applies to   : Sirf Classification tasks
  Input        : X_train, y_train
  Output       : Balanced X_train, y_train

  Problem:
    Class 0 (Not Survived): 700 samples
    Class 1 (Survived)    :  50 samples   ← minority
    Model sirf 0 predict karega — easy accuracy milegi

  Solution — SMOTE (Synthetic Minority Oversampling Technique):
    Minority class ke synthetic (fake-but-realistic) samples banao
    Jab tak dono classes roughly equal na ho jayein

  Config: IMBALANCE_THRESHOLD = 0.2
    Minority ratio < 20% → SMOTE apply karo
    Minority ratio >= 20% → data balanced hai, skip karo

  IMPORTANT: SMOTE sirf TRAINING data pe apply hota hai.
             Test data kabhi touch nahi hota.

STEP 10b — Smart Model Selection + Reason  [NEW in v2]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Kya hota hai : Best model choose karo + reason clearly explain karo

  Case 1 — No Tie (ek clear winner):
    → Highest score wala model seedha winner
    → Reason print hota hai: kyun choose kiya, model ki nature kya hai

  Case 2 — Tie (multiple models same score pe):
    → 3 steps mein winner decide hota hai:

    Step A — Priority Order:
      Simpler models ko prefer karo jab accuracy same ho
      Order: Logistic → Naive Bayes → KNN → DT → SVM →
             Bagging → AdaBoost → Extra Trees → GB →
             RF → LightGBM → XGBoost → Voting

    Step B — Cross Validation (5-fold):
      Tied models pe CV run karo
      CV mean aur std print hota hai

    Step C — Final Decision:
      CV difference > 0.005 → Better CV wala jitega
      CV difference <= 0.005 → Priority order wala jitega (simpler model)

  Why simpler model in a tie?
    • Faster prediction
    • Easier to explain
    • Less overfitting risk
    • Easier to debug
